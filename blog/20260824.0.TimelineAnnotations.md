# Stage One: Timeline Annotations

**Date:** 24 August 2026

## Objective

We continued Stage One by making time on the call timeline something a person can mark, name, and share.

The previous recording work left a per-speaker waveform that could be scrubbed and played. Time selection on that graph was still an ephemeral overlay, and the recording post explicitly left annotations out of scope. A range existed only on one device, vanished on reload, and could not tell anyone else *what* had just been noticed.

The objective was to make **selection** and **annotation** first-class, independently creatable, and optionally linked — then persist them through the same PostgreSQL, outbox, and WebSocket path used for messages and call lifecycle.

The most important outcome is that a conversation member can park a labeled mark on the graph the instant they know what kind of thing they heard, and every other member sees that box before any note is written.

## Selection Is When. Annotation Is What.

A selection is **when** and (usually) **who**: `[startMs, endMs]` plus a scope of all channels or one participant track.

An annotation is **what**: a seeded **profile** (name, color, icon). The timeline label is the profile name. An optional free-text **note** lives in an inspection frame outside the graph and is skippable.

Either object can exist alone. Linking them is 1:1 provenance. An annotation created with no selection is a point (`startMs === endMs`) at the playhead, or at the live edge if the viewport is following live. It still appears on the graph as a compact labeled chip.

Tap an annotation: highlight its box and open the inspection frame **between the timeline and chat**, not inside the waveform.

## Persist Immediately, Complete Later

The fast path is the product. Press-and-hold **Annotate**, slide to a profile, release. A short tap opens the same list.

Releasing a profile `POST`s immediately with `note: null`. The inspection frame is an editor of a row that already exists, never a create form. Later edits — note, link, range — are `PATCH` and broadcast `annotation.updated`. Peers see the labeled box as soon as the profile is chosen, even while the paperwork is empty.

Closing the frame without a note is success, not an abandoned draft.

## Channel-Scoped Selection

Select mode plus horizontal pan remains. The **press Y** at pan begin chooses scope:

- Drag starts on the **ruler** → all channels (full-height green rect).
- Drag starts on a **participant waveform** → that track only (rect clipped to that row).

Solo remains a separate hearing filter.

A committed selection shows **left and right resize handles**. Hit slop is about 24 px. Handles stay available after Select mode is turned off. Dragging a handle moves that edge, keeps a 50 ms minimum width, and cannot cross the opposite edge. Persist on gesture end (`POST` or `PATCH`).

## Snap to Speech (Energy)

There is still no transcript. Word-level snap waits on ASR. What we already have is 20 Hz waveform amplitudes (50 ms bins) on each track.

On create-drag end and resize-handle end — not mid-stroke — each moved edge snaps to the nearest speech boundary in a ±400 ms window:

- A **start** edge snaps to onset (quiet → speech).
- An **end** edge snaps to offset (speech → quiet).
- Single-channel uses that track. All-channel uses any visible track.
- If nothing is in range, the edge stays where the finger left it.
- Times round to integer call-offset milliseconds before they hit the API. Gesture clocks are floats; Zod used to reject them as non-integers.

This is coarse. Coughs, laughter, and noise can look like speech. It is good enough to park a handle on a talk spurt.

## Data Model

Three new tables, plus a migration that seeds the profile catalog (stable UUIDs, not only `seed.ts`):

```text
annotation_profiles
call_selections
call_annotations
```

The six system profiles are:

```text
Decision    amber   #f59e0b   gavel
Action      sky     #38bdf8   flag
Question    violet  #c084fc   help-outline
Agreement   green   #4ade80   check-circle
Concern     rose    #fb7185   warning
Highlight   yellow  #facc15   star
```

A selection stores `start_offset_ms`, `end_offset_ms`, and nullable `user_id` (`null` means all channels).

An annotation always stores a location (`start` / `end`, equal when unbound), nullable `user_id` for marker scope, nullable `note`, and a nullable **unique** `selection_id`. If a selection is linked, the annotation’s stored range and scope stay in sync with it. Timeline rendering uses the annotation columns for the labeled box, and unlinked selections for unlabeled green ranges.

Conversation members can create and view. Only the **author** can update, delete, link, or unlink. Truncating test data leaves the seeded profiles in place.

## API and Events

Member-gated REST on the existing call router:

```text
GET    /api/v1/annotation-profiles
GET/POST    /conversations/:id/calls/:callId/selections
PATCH/DELETE .../selections/:selectionId
GET/POST    /conversations/:id/calls/:callId/annotations
PATCH/DELETE .../annotations/:annotationId
```

POST annotation does not require a note. Completeness is not a write precondition.

Domain events, written in the same transaction as the row via the outbox:

```text
annotation.created
annotation.updated
annotation.deleted
selection.created
selection.updated
selection.deleted
```

Payloads carry a profile snapshot, offsets, scope, `selectionId`, and `createdBy`, so a peer can render the box without a refetch. A websocket consumer fans those events out to conversation members.

## Client

`CallTimeline` now takes a first-class model: `ChannelScope`, `TimelineSelection`, `TimelineAnnotation`.

The **Annotate** control is a press-and-hold profile picker. Markers sit in the same clipped waveform overlay as the selection, and they apply the same pan shift as the bars, so chips move with the graph instead of waiting for a committed `viewStartMs`. The inspection frame PATCHes note and delete. **Link** appears when a working selection and a selected annotation both exist.

The conversation screen loads profiles and annotations with the call, applies live `annotation.*` events, and persists selections on pan-end. The sandbox at `timeline-test` keeps in-memory fixtures so picker, markers, and inspect can be exercised without the API.

Play starts from the playhead the user placed. A leftover selection or a range annotation no longer yanks playback back to the start of the track. Tapping the waveform always seeks; tapping a marker still selects it. If the playhead sits inside a range, playback can still stop at that range’s end.

Background fetches (recordings poll, timeline refresh, inspect mutations) catch network failures instead of throwing uncaught `ApiError` overlays. The recordings poll skips a tick while one request is already in flight, so a slow `/recordings` call cannot stack ten overlapping 10-second timeouts.

## Session Playback

Ingest still files 500 ms stereo WAV clips so a clip can be playable ~0.5 s behind live. Replay was starting a new player on every clip, and the playback clock was re-seeking every animation frame while each file loaded. A few minutes of call is hundreds of those handoffs.

Play now asks the API for one concatenated WAV per recording session (`GET .../recordings/:recordingId/media`). The object store gained `get` / `exists` so the server can stitch PCM, cache the result under the session prefix, and return a presigned URL. The player only seeks when the user jumps or when drift exceeds about a second. Clips that land after Play has already started still attach as a short live tail.

## Automated Tests

Repository and HTTP coverage now includes:

```text
profile catalog seed
point annotation (equal offsets, no selection, note null)
annotation linked to a selection (range and scope copied, still note-null)
later PATCH note emits annotation.updated
channel-scoped vs all-channel selection
link / unlink / author-only mutate
fractional gesture offsets rounded on write
member vs non-member access
session WAV concat from sequential fragments
```

There is still no dedicated mobile test runner. Conversation plus `timeline-test` remain the client check.

## Out of Scope

Still later:

- Custom / user-defined profiles
- Structured metadata beyond the optional note
- Voice-memo annotations
- Word-level / transcript snap
- Dragging the selection body to move it, multi-select

## Current Status

The following additional work is now complete:

- `annotation_profiles`, `call_selections`, and `call_annotations` schema, migration, and six seeded profiles
- Persist-immediately annotation create with `note` null, then PATCH to complete
- `annotation.*` and `selection.*` outbox events and websocket fan-out
- Channel-scoped Select (ruler vs track), resize handles, and energy snap on gesture end
- Profile picker, graph markers, and an inspection frame outside the timeline
- Live peer visibility of incomplete annotations
- Play from the placed playhead
- Session-level concatenated playback instead of stitching 500 ms players on the client

## Next Step

Stage One now lets a person mark a moment on the same per-speaker timeline used to talk, and share that mark before they have written a sentence about it.

The next likely work includes word-level snap once a transcript exists, richer annotation metadata, production object storage and identity, and video on the existing `media_mode` path — still without mixing tracks.

The objective remains:

> **Record human communication in a durable, structured, event-driven system while preserving the natural communication experience—and establish the foundation from which a future semantic model can emerge without rebuilding the communication layer.**
